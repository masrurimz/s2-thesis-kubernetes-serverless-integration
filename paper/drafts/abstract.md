The Kubernetes Horizontal Pod Autoscaler (HPA) adds pods only after load rises, and if nodes are full, a new virtual machine takes one to two minutes to start while requests wait. A forecast can add pods early. A serverless platform can instead absorb the extra load within seconds at a higher price, so hybrids keep the base load on Kubernetes and send only the overflow to serverless. We test whether a forecast still helps once serverless covers this delay, in a hybrid of Kubernetes and the serverless platform Knative. Every 15 s, a router sends Knative only the load the ready pods cannot serve, and a scaler adapted from the forecast-based autoscaler ElaX sets the pod count. The reactive hybrid uses only the observed load, and the predictive one adds a 135 s gated recurrent unit (GRU) forecast plus a safety margin. On a ClarkNet trace replay, both hybrids had the projected cost of Kubernetes with the HPA, while Knative alone had the lowest 99th-percentile latency (p99) at over twice that cost. In ten confirmatory pairs, the forecast added 45% more pod-seconds, but the p99 did not change measurably (-13.6 ms, 95% CI [-63.5, +35.6], p = 0.307). With ten pairs, the test detects differences of about 72 ms or more. The GRU itself was no more accurate than a linear autoregression. A likely, untested explanation is that the serverless platform already serves the load while new pods start, leaving the forecast little delay to remove.
